# 문제 해결 기록

개발 과정에서 겪은 문제를 **현상 → 원인 → 해결 → 결과** 순서로 정리한 문서입니다. 수치는 개발 중 실제로 측정한 값입니다.

[← README로 돌아가기](../README.md)

### 1. 짧은 이상행동을 놓치는 미탐
- **문제**: 10초 영상 중 2초짜리 담 넘기가 정상으로 판정됐습니다(오차 0.93 < 임계값 1.57).
- **원인**: 영상 전체를 시간 평균·표준편차로 하나의 벡터로 압축해서, 서 있는 구간에 이상 구간이 희석됐습니다.
- **해결**: 1초 윈도우·0.5초 간격으로 분할하고 구간 오차의 최댓값으로 판정하도록 바꿨습니다.
- **결과**: 같은 영상의 오차가 1.57로 임계값(0.84)을 넘어 검출됐고, 기존 정상·비정상 영상의 판정은 유지됐습니다.

### 2. 임계값 불안정과 학습 재현성
- **문제**: 재학습할 때마다 임계값이 크게 변했고, 정상 영상의 일부 구간이 임계값을 넘었습니다.
- **원인**: 정상 표본이 적었고 학습 seed가 고정되어 있지 않았습니다.
- **해결**: 증강으로 샘플을 3배로 늘리고, seed를 고정하고, seed 3개(42, 0, 123)로 교차검증했습니다. percentile(95th/99th) 임계값과도 비교했습니다.
- **결과**: 동일 seed 3회 학습 결과가 완전히 일치했고, 100epoch loss는 0.570 → 0.135로 내려갔습니다. 정상 영상의 임계값 여유는 seed 고정 전 최소 +0.0075에서 3개 seed 교차검증 최소 +0.055로 늘었습니다. 세 임계값 방식의 판정 결과는 같았습니다.

### 3. 촬영 조건이 만든 정상 영상 오탐
- **문제**: 정상 서기·걷기 영상에서 임계값을 넘는 구간이 생겼습니다.
- **원인**: 구간별 오차를 시간순으로 출력해 진단한 결과, 행인이 지나가며 추적 대상이 바뀌는 구간과 카메라 패닝 구간이었습니다.
- **해결**: 학습용 정상 영상을 단독 인물·고정 카메라·전신 노출 기준으로 선별하고 재촬영했습니다.
- **결과**: 해당 구간의 임계값 초과가 사라졌습니다.

### 4. 서비스 경로와 실행 환경 불일치
- **문제**: 웹 분석 API가 개선 전 RandomForest 추론을 호출해서 Autoencoder가 서비스에 반영되지 않았습니다. 학습 스크립트도 캐시를 쓰지 않았고, MediaPipe 최신 버전에서 `solutions` API가 제거되어 팀원 환경에서 실행 오류가 났습니다.
- **해결**: `/predict/video`를 Autoencoder 판정 경로로 연결하고 웹에서 end-to-end로 테스트했습니다. 학습 스크립트가 캐시를 쓰는 데이터셋 함수를 호출하도록 바꾸고, MediaPipe 버전을 requirements에 고정했습니다.
- **결과**: 서비스가 개선된 모델을 사용하고, 팀원 환경에서 의존성 오류가 해소됐습니다.

### 5. 실시간(RTSP) 적용 검증
- 실시간 경로와 업로드 경로가 같은 판정 함수를 쓰도록 구현하고, 같은 영상을 두 경로로 돌려 오차값이 일치함을 확인했습니다(peak error 18.7143 동일).
- 실제 카메라 프레임에 하반신이 잡히지 않아 발목 좌표가 화면 밖으로 벗어나는 문제를 좌표 진단으로 찾아, 카메라 각도를 조정해 해결했습니다.

### 6. 알림이 쌓이지 않던 문제 추적
- **현상**: 실시간 감지를 해도 알림 내역이 9월 이후 늘지 않았습니다.
- **원인**: AI 서버에 백엔드 주소(`BACKEND_URL`)가 설정되지 않았고, 카메라의 `video_source_id`가 전달되지 않았으며, 그 원인은 영상 리셋이 CCTV 영상 소스까지 삭제 처리해 화면이 카메라를 찾지 못한 것이었습니다.
- **해결**: 영상 리셋이 업로드 영상(UPLOAD)만 숨기도록 백엔드를 수정했습니다. 이미 삭제 처리된 CCTV 소스는 DB에서 복구했고, AI 서버 실행 시 `BACKEND_URL`을 지정하도록 실행 방법에 명시했습니다.
- **결과**: 리셋 후에도 CCTV 영상 소스가 유지되어 알림이 계속 쌓입니다.
